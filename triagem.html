Quem chega primeiro não é quem é atendido primeiro. Quem corre mais risco é.

Este é o sistema de acolhimento e classificação de risco da unidade. O paciente preenche a própria ficha, a enfermagem mede os sinais vitais e define a cor do atendimento.

Sistema de demonstração acadêmica · Dados tratados conforme a Lei 13.709/2018 (LGPD)

Manual do sistema

Escolha o seu perfil e veja exatamente o que fazer, na ordem.

Paciente

  1. Na página inicial, toque em Sou paciente.
  2. Primeira vez? Use a aba Criar cadastro. Preencha nome, nome social (se usar), CPF, RG, data de nascimento, endereço, doenças, alergias e os contatos de emergência. O CPF e uma senha serão seus dados de entrada.
  3. Marque o consentimento da LGPD. Sem ele o cadastro não é salvo — é a base legal que autoriza a unidade a tratar seus dados.
  4. Já tem cadastro? Aba Entrar: CPF + senha.
  5. Dentro do painel, abra Abrir atendimento: descreva o que está sentindo, há quanto tempo, quem veio com você e escolha a carinha que representa sua dor, de 1 a 10.
  6. Envie. Sua ficha entra na fila da enfermagem na hora e você recebe uma senha de chamada.
  7. Em Meu histórico você vê todas as suas idas anteriores, a cor que recebeu e o que foi registrado.

Enfermeiro(a)

  1. Página inicial → Sou enfermeiro(a). Entre com nome, CPF, RG e número do COREN. Na primeira vez o sistema cria o seu acesso com esses dados e uma senha.
  2. Você cai na fila de triagem, ordenada por prioridade: primeiro quem ainda não foi classificado, depois vermelho, amarelo e verde.
  3. Clique na linha do paciente. À direita abre a ficha completa: identificação, doenças, alergias, medicação de uso, acompanhante, motivo da vinda e a dor marcada.
  4. Preencha os sinais vitais: P.A., P.A.G., frequência cardíaca, frequência respiratória, temperatura, saturação e glicemia.
  5. Escolha a bolinha de risco: verde (menos arriscado), amarelo (importante) ou vermelho (risco de vida). A cor aparece na tabela para toda a equipe imediatamente.
  6. Escreva a evolução em Anotações da enfermagem e salve. Ao fim, use Encaminhar / finalizar — a ficha sai da fila e vira histórico do paciente.

Técnico(a) em enfermagem

  1. Página inicial → Sou técnico(a). Entre com nome, CPF, RG e número do COREN (registro de técnico).
  2. A fila é a mesma que o enfermeiro vê, com uma diferença: CPF e RG dos pacientes aparecem mascarados (•••.456.•••-••). É o princípio da necessidade da LGPD — você vê só o que precisa para o cuidado.
  3. Você registra sinais vitais e medidas normalmente, e pode sugerir a cor do risco.
  4. Toda cor marcada por técnico fica com a etiqueta “a confirmar” até um enfermeiro validar. A classificação de risco é privativa do enfermeiro (Resolução COFEN 423/2012).
  5. Finalizar atendimento também é ação do enfermeiro.

O que o sistema faz para cumprir a LGPD

Dado de saúde é dado pessoal sensível (art. 5º, II da Lei 13.709/2018). Ele exige cuidado maior do que um dado comum. O que está implementado aqui:

  • Consentimento registrado — data, hora e versão do termo ficam gravadas junto do cadastro.
  • Finalidade declarada — os dados são coletados para triagem e atendimento, e nada mais.
  • Minimização e necessidade — cada perfil vê o mínimo necessário: o técnico recebe CPF e RG mascarados.
  • Controle de acesso — só entra quem se identifica; profissional entra com COREN.
  • Registro de operações (trilha de auditoria) — quem abriu qual ficha, quem alterou o quê e quando. Fica em Privacidade na área do paciente.
  • Direitos do titular — o paciente pode ver, exportar em arquivo e excluir seus dados pelo próprio painel (arts. 18 e 19).
O que falta para uso real em hospital: HTTPS obrigatório, senhas com hash forte (bcrypt/argon2) no servidor, criptografia do banco em repouso, backup, política de retenção do prontuário (o CFM exige guarda mínima de 20 anos), nomeação de encarregado de dados (DPO) e relatório de impacto. Este projeto é uma demonstração acadêmica — não coloque dados reais de pacientes nele.

Como o site foi feito

HTML é o esqueleto (os campos, as tabelas, os botões). CSS é a aparência (cores, espaçamentos, a régua verde-amarelo-vermelho). JavaScript é o comportamento (validar CPF, animar as carinhas, ordenar a fila). O banco de dados é a memória: onde pacientes, atendimentos e o log de auditoria ficam guardados.

CREATE TABLE paciente (
  id            SERIAL PRIMARY KEY,
  nome          VARCHAR(120) NOT NULL,
  nome_social   VARCHAR(120),
  cpf           CHAR(11) UNIQUE NOT NULL,
  rg            VARCHAR(20),
  nascimento    DATE NOT NULL,
  cartao_sus    VARCHAR(20),
  govbr         VARCHAR(120),
  telefone      VARCHAR(20),
  endereco      JSONB,
  senha_hash    VARCHAR(255) NOT NULL,
  consent_em    TIMESTAMP,
  consent_versao VARCHAR(10),
  criado_em     TIMESTAMP DEFAULT now()
);

CREATE TABLE condicao_saude (      -- alergias, diabetes, cardiopatia...
  id          SERIAL PRIMARY KEY,
  paciente_id INT REFERENCES paciente(id) ON DELETE CASCADE,
  tipo        VARCHAR(30),         -- 'alergia' | 'doenca' | 'medicamento'
  descricao   TEXT
);

CREATE TABLE profissional (
  id        SERIAL PRIMARY KEY,
  nome      VARCHAR(120) NOT NULL,
  cpf       CHAR(11) UNIQUE NOT NULL,
  rg        VARCHAR(20),
  coren     VARCHAR(20) UNIQUE NOT NULL,
  papel     VARCHAR(12) CHECK (papel IN ('enfermeiro','tecnico')),
  senha_hash VARCHAR(255) NOT NULL
);

CREATE TABLE atendimento (
  id             SERIAL PRIMARY KEY,
  paciente_id    INT REFERENCES paciente(id),
  senha_chamada  VARCHAR(10),
  aberto_em      TIMESTAMP DEFAULT now(),
  motivo         TEXT,
  sintomas       TEXT,
  dor            SMALLINT CHECK (dor BETWEEN 0 AND 10),
  risco          VARCHAR(10) CHECK (risco IN ('verde','amarelo','vermelho')),
  risco_por      INT REFERENCES profissional(id),
  risco_confirmado BOOLEAN DEFAULT FALSE,
  status         VARCHAR(15) DEFAULT 'aguardando',
  acompanhante   JSONB,
  anotacoes      TEXT
);

CREATE TABLE sinais_vitais (
  id             SERIAL PRIMARY KEY,
  atendimento_id INT REFERENCES atendimento(id) ON DELETE CASCADE,
  medido_em      TIMESTAMP DEFAULT now(),
  medido_por     INT REFERENCES profissional(id),
  pa             VARCHAR(10),      -- 120/80
  pag            VARCHAR(10),
  fc SMALLINT, fr SMALLINT, temperatura NUMERIC(4,1),
  saturacao SMALLINT, glicemia SMALLINT
);

CREATE TABLE auditoria (           -- exigência prática da LGPD
  id         SERIAL PRIMARY KEY,
  quando     TIMESTAMP DEFAULT now(),
  quem       VARCHAR(120),
  papel      VARCHAR(20),
  acao       VARCHAR(60),
  alvo       VARCHAR(60)
);

Para rodar isso de verdade: Node.js + Express no servidor, PostgreSQL ou MySQL como banco, bcrypt para senhas e JWT para a sessão. O HTML/CSS/JS desta página continua igual; só as funções que hoje leem e gravam dados passariam a chamar o servidor com fetch().
